# GaugeFixer: Overcoming Non-identifiability in Sequence-to-Function Models

In this folder, we provide code and data necessary to reproduce the analysis performed in the manuscript describing GaugeFixer.

### Requirements

The following Python libraries are required for reproducing the results:

- gaugefixer
- seaborn
- matplotlib
- logomaker
- scipy

### Environment setup

The repository root contains a `pyproject.toml` and `uv.lock` that pin a working
environment. With [uv](https://docs.astral.sh/uv/) installed, run this once from
the repository root:

```bash
uv sync
```

This creates `.venv/` with Python 3.12 and all dependencies. Prefix each command
below with `uv run` (e.g. `uv run python manuscript/code/fig2_benchmark.py`), or
activate the environment with `source .venv/bin/activate` and use `python`
directly.

**All scripts use paths relative to the repository root, so they must be run
from the repository root** — not from `manuscript/code/`.

### Figure workflow

Script names are prefixed with the manuscript figure (and panel letters) they
produce, so `fig3BCD_theta.py` generates panels B, C, and D of Figure 3.

Scripts write individual panels to `manuscript/results/` with a `_raw` suffix,
which marks them as direct script output that has **not** been through Adobe
Illustrator. Those `_raw` panels are placed into `manuscript/figures/fig.ai`,
where panel letters (A, B, …) are added by hand, and the assembled figures are
exported as `manuscript/figures/fig1_illustration.pdf`, `fig2_benchmarks.pdf`,
and `fig3_shinedalgarno.pdf` — the three files `manuscript/main.tex` includes. Those
exports are produced manually and are not generated by any script.

Figure 1 is drawn entirely in Illustrator and has no corresponding script.

The complete workflow directly with the following bash script

```bash
bash run_all.sh
```

### Benchmarking analysis (Figure 2)

First, we compute the memory and computational requirements and scaling with the number of parameters for the different models:

```bash
uv run python code/fig2_benchmark_run.py
```

This will create a file with the running times and memory requirements over 10 different iterations for each model configuration. Note this takes roughly 10 minutes, as it sweeps pairwise protein models up to L=150.

To make the figures representing these computational requirements, run

```bash
uv run python code/fig2_benchmark.py
```

### Shine-Dalgarno sequence analysis (Figure 3)

Here we use `GaugeFixer` to analyze the fitness landscape of the Shine-Dalgarno sequence.

We first compute the gauge-fixed parameters in the different hierarhical gauges of interest by running

```bash
uv run python code/fig3_fix_gauge.py
uv run python code/fig3_fix_gauge_extended_core.py
```

`fig3_fix_gauge.py` fixes the gauge around the 5-nt `AGGAG` core at each
register; `fig3_fix_gauge_extended_core.py` does the same for the extended 6-nt
`GAGGAG` and `AGGAGU` cores. Both are required before plotting, since
`fig3BCD_theta.py` reads the outputs of each.

Then, we make the plots corresponding to the sequence probability distributions that represent the different peaks in the landscape and plot the gauge-fixed coefficients in the hierarchical gauges defined by them:

```bash
uv run python code/fig3A_pi.py
uv run python code/fig3BCD_theta.py
```

`fig3BCD_theta.py` produces three separate panel files. The module-level flags
`plot_theta_0`, `plot_theta_lc_lclc`, and `plot_theta_scatter` at the top of the
script can be set to `False` to regenerate only a subset of them.

### Output

Expected output files:

Results tables

- `results/benchmarking.csv`: this file contains the results of the benchmarking analysis.
- `results/theta_fixed.aligned.csv`: this file contains the values of the gauge-fixed parameters aligned by the core positions.
- `results/theta_fixed.GAGGAG.aligned.csv`, `manuscript/results/theta_fixed.AGGAGU.aligned.csv`, `manuscript/results/theta_fixed0.extended_core.csv`: the corresponding values for the extended 6-nt cores.

Figure panels

Each panel is written to `results/` in three formats — `.pdf`, `.png`
(300 dpi), and `.svg` — all with opaque white backgrounds.

- `fig2_benchmarks_raw`: benchmarking results — runtime (panel A) and peak memory (panel B).
- `fig3A_pi_raw`: logo plots representing site-independent probability distributions.
- `fig3B_theta0_raw`: the gauge-fixed constant parameters in each of the corresponding hierarchical gauges.
- `fig3C_theta_raw`: the gauge-fixed additive and pairwise parameters in each of the corresponding hierarchical gauges.
- `fig3D_theta_scatter_raw`: panels comparing the parameters of local pairwise models in each of the corresponding hierarchical gauges.

Note that `fig2_benchmarks_raw` holds both panels A and B of Figure 2 in a single
file, and `fig3C_theta_raw` holds both the additive heatmaps and the pairwise
triangle plots that together make up panel C of Figure 3, since in each case the
plots share one matplotlib figure.
